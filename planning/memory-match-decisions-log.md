# Quilt Picnic, website side: decisions made while the owner was away (2026-11-13)

Scope: website support only (progress store, player, pages, catalog, tests). The game is built in another repo and synced by
the owner. Each entry: what, why, how hard to change.

1. **Quilt cap is 200, and past it the OLDEST patches fold into a `folded` count.** The design said "at most 200 per child per game"
   and the word wall's rule is "new items past the cap are not added". That rule would freeze a quilt, and the game picks the next
   patch from the newest one on the quilt, so the pattern would freeze too. Folding keeps the newest and the total exact. Easy to change
   (`QUILT_MAX_PATCHES`, `stitch()` in `progress.ts`).
2. **Each stored patch keeps its reward `id`.** The design sketch had `{ patch, at, session }` only, but repeats of a patch slug are
   normal, so the reward id is the only dedupe key. Without it a replayed session could not be recognised on the quilt.
3. **HostInit sends the newest 64 patches, oldest first.** The kit design recommends at most 64. The mini quilt shows 9 and the end
   screen 16, so 64 is far more than needed and still small (about 1 KB).
4. **At most one patch per question, never more patches than questions.** A pair-match question is one board, so this is the same rule
   as seeds and word cards. It bounds a buggy game.
5. **Patch slug format is `^[a-z][a-z0-9-]{0,31}$`.** Kit slugs look like `gingham-red`. Strict on purpose, like word ids, because
   slugs go back to the game and may be shown on a parent page later. Upper case or markup is dropped.
6. **`misses` is stored as a plain number on the stored session (0 or more).** It is a fact for the future parent page and is never
   sent back to the child's game. It is kept for any record that carries it, not only pair-match. Junk (negative, NaN, a string) is ignored.
7. **No parent tip from misses.** Letter Workshop got tips because its mistakes have kinds. A memory miss has no kind, and
   `mistakes` stays `{}`, so there is nothing honest to say yet. The Grown-ups page lists the new skill like the others.
8. **Skill id is `logic-memory.memory.matching-pairs`** (the kit's validator wants the subject prefix, see pair-match-design.md,
   section 12, item 5). `skills.json` gets `subject: "logic"`, grades Pre-K and K, `topDifficulty` 5 (five levels).
9. **Grade codes `prek` and `k`** in the catalog, which `GameCard` already prints as "Pre-K, Kindergarten".
10. **URL `/logic-games/memory-match-for-preschool/`, H1 and title "Memory Games for Preschool and Kindergarten".** The owner asked for
    a title around that phrase. The catalog `keywordTitle` is the same phrase, so the card, breadcrumb and H1 agree. The card heading is
    long; shorten `keywordTitle` and the page H1 together if it looks heavy.
11. **Navigation label "Memory games"** for the `logic-games` category (as the owner said), the same way `language-games` says "Reading
    games". The home page card is still called "Logic and memory" because it will hold patterns and odd one out too.
12. **"Memory flip cards" removed from the coming-soon list**, since it is now ready (same as Word building was).
13. **Placeholder poster path and PENDING commit.** The catalog points at `play/memory-match-prek/poster.webp`, which does not exist
    until the owner generates the poster and runs the sync. Until then the card and page images 404 (like Letter Workshop before its
    sync). The smoke test counts those 404s and reports the count, it does not hide them. `source.commit` is `PENDING` and the sync
    script fills it in.
14. **Page copy claims only what the kit design promises:** flaps, a soft note on a match, Peek after 3 misses in a row and Sparkle
    after 6, a new layout each session, five levels (2 to 8 pairs), the quilt kept on the device, no score or counter shown. Level 5 is
    described loosely ("friends that look alike") because the design says it ships only after the owner has tried levels 1 to 4. If
    level 5 changes, edit the "What kids learn" list on the game page. I did not claim "hard pictures come back" because I could not
    confirm the game feeds `practiceItems`.
15. **Category page speaks of Grade 1 and 2 logic games (odd one out, patterns) as "planned next".** They are on the coming-soon list.
    No promise of dates.
16. **Privacy page names the quilt and the miss count**, and its "last updated" date stays 13 November 2026 (today).
17. **No new rule for the Grown-ups page and no "My quilt" page.** The design says the parent page is a later follow-up.
18. **Sitemap needed no edit.** It is generated by `@astrojs/sitemap` from the built pages, and the smoke test checks that both new
    URLs are in it and no `/play/` URL is.
19. **Smoke test handles the missing build with a labelled STAND-IN frame, not by skipping.** The frame opens on the site's own 404
    page (same origin, same sandbox, so `player.ts` applies its real origin and source checks) and posts `GameReady` itself. Every
    check prints `[STAND-IN frame (game build not synced)]` in its name. It proves the website side only. One real-game line
    prints `SKIPPED: game build not synced`. After the sync, the checks print `[real game frame]` and the SKIPPED lines vanish.
20. **No changes to `public/play/` and no sync run**, as asked. `npm ci` was run to get a build (node_modules is not committed).
21. **Protocol stays 1.** The only additions are optional fields (`HostInit.quilt`, `kind: "patch"` rewards, `misses`), which old and
    new sides ignore if they do not know them.
